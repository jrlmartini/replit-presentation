Implemente uma evolução do design system de slides do meu sistema de apresentações (Conatus Presentation System) para suportar layout variants escaláveis com slots, mantendo controle por schema + registry + validator.

Objetivo

Atualmente o sistema já gera apresentações e possui slide types/componentes básicos. Quero evoluir a diagramação para suportar:

slides claros e escuros

layouts com 1, 2 e 3 colunas

layouts com ícones (3 horizontal, 4 horizontal, 3 vertical com frase de destaque)

conteúdo em colunas com texto, bullets, imagens e ícones

seleção robusta de layouts pela LLM sem perder consistência visual

Requisitos de arquitetura (obrigatórios)
1) Não explodir o número de slide types

Usar:

slideType semântico

layoutVariant geométrico

slots de layout

Ou seja:

slide.type define a intenção semântica (conteúdo, ícones, gráfico)

slide.layout.name (ou layoutVariant) define a geometria

components[].slot define onde cada componente entra

2) Criar regras por slideType + layoutVariant + slot

Refatorar o registry/validator para validar:

layout variants permitidos por slide type

slots permitidos por variant

componentes permitidos por slot

quantidade min/max por slot

regras obrigatórias (ex.: chart + texto em chart slides)

3) Adicionar componente composto para layouts de ícones

Criar novo componente:

icon_feature_item

Conteúdo esperado:

iconSrc?: string

iconName?: string

title: string

text: string

Esse componente será usado nos layouts:

icons_3_horizontal

icons_4_horizontal

icons_3_vertical_with_quote

4) Manter compatibilidade com o pipeline atual

Não quebrar renderização atual

Se possível, adicionar suporte incremental

Viewer continua renderizando a partir de deck_ast validado

Components já existentes continuam funcionando
